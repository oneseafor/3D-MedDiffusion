## 十、分模态训练架构

### 10.1 数据格式澄清

| 模态 | 输入尺寸 | D维度含义 |
|------|----------|----------|
| cine4ch | (256, 256, 25) | 25帧时间 |
| cinesax | (256, 256, 25) × 3 | 25帧时间 × 3切面 |
| lgesax | (256, 256, 6) | 6帧（时间或空间） |

**关键决策：**
- 输入：完整3D数据 (H, W, D)，保持原始D维度
- 输出：单帧/单层 (H, W, 1)
- 不区分D维度是时间还是空间

### 10.2 分模态训练策略

由于不同模态D维度不同（25 vs 6），采用分模态训练：

| 模型 | 处理模态 | D维度 | batch_size |
|------|----------|-------|------------|
| Cine模型 | cine4ch + cinesax | 25 | 4 |
| LGE模型 | lgesax | 6 | 16 |

### 10.3 配置更新

**configs/cardiac_pipeline.yaml:**
```yaml
model:
  cine:
    autoencoder:
      patch_size: 128
      patch_depth: 25
      downsample: [8, 8, 8]
    diffusion:
      image_size: [16, 16, 25]

  lge:
    autoencoder:
      patch_size: 128
      patch_depth: 6
      downsample: [8, 8, 1]  # D维度不下采样
    diffusion:
      image_size: [16, 16, 6]

training:
  cine:
    batch_size: 4
  lge:
    batch_size: 16
```

### 10.4 代码修改

**data_loaders/cardiac_dataset.py:**
- 新增 `modality_type` 参数："cine" 或 "lge"
- 新增 `patch_depth` 参数：cine=25, lge=6
- 修改 `_extract_patch()` 方法：H,W 随机裁剪，D 保持完整
- 修改 `__getitem__()` 方法：根据 modality_type 加载数据
- 修改 `build_cardiac_dataloader()` 函数：支持分模态

**verify_config.py:**
- 支持 `--cine` 和 `--lge` 参数分别验证
- 显示各模态的模型配置和训练配置

### 10.5 Latent 空间

| 模型 | 输入尺寸 | latent尺寸 | 计算公式 |
|------|----------|------------|----------|
| Cine | (128, 128, 25) | (16, 16, 25) | H,W: 128/8=16, D: 25 |
| LGE | (128, 128, 6) | (16, 16, 6) | H,W: 128/8=16, D: 6 |

## 十八、PatchVolume.py 验证阶段 unfold 错误修复

### 18.1 错误描述

训练启动后，在 Sanity Checking 阶段出现错误：

```
RuntimeError: maximum size for tensor at dimension 2 is 25 but size is 128
```

**错误位置：** `AutoEncoder/model/PatchVolume.py` 第 229 行

**原因：** `PatchVolume.py` 的 `forward` 方法在 `val=True` 时会对所有维度进行 unfold 操作：
```python
x_input = x.unfold(2,self.patch_size,self.patch_size).unfold(3,self.patch_size,self.patch_size).unfold(4,self.patch_size,self.patch_size)
```

这要求 D, H, W 都 >= `patch_size`（128），但我们的心脏 MRI 数据：
- Cine: D=25, H=128, W=128
- LGE: D=6, H=128, W=128

D 维度太小，无法进行 unfold。

### 18.2 问题分析

原始项目处理的是真正的 3D 体积（CT 扫描），所有维度都很大（如 256×256×256）。

我们的心脏 MRI 数据 D 维度是时间帧（25帧或6帧），不是空间维度，不适合这种处理方式。

### 18.3 修复方案

修改 `AutoEncoder/model/PatchVolume.py` 的 `forward` 方法：

**Stage 1 训练和验证：**
- 跳过 unfold 操作，直接使用原始数据
- 不再对维度进行切片

**Stage 2 训练：**
- 如果所有维度 >= patch_size，进行原始的 unfold 操作
- 否则直接使用原始数据

### 18.4 代码修改

```python
def forward(self, x, optimizer_idx=None, log_volume=False,val=False):
    B, C, D, H, W = x.shape

    # Check if all dimensions are >= patch_size for unfold
    can_unfold = (D >= self.patch_size) and (H >= self.patch_size) and (W >= self.patch_size)

    if self.stage == 1:
        # Stage 1: no unfold needed for both train and val
        x_input = x

    elif can_unfold:
        # Stage 2 with large enough dimensions: unfold all
        x_input = x.unfold(2,self.patch_size,self.patch_size)...

    else:
        # Stage 2 with small D (e.g., cardiac MRI): use directly
        x_input = x

    # ... encoder, codebook ...

    if self.stage == 1:
        # Stage 1: direct decode for both train and val
        x_recon = self.decoder(self.post_vq_conv(embeddings))

    else:
        # Stage 2: need to rearrange patches
        if can_unfold:
            # Original path: unfold all dimensions
            ...
        else:
            # Dimensions too small for unfold: use directly
            pass
        x_recon = self.decoder(self.post_vq_conv(embeddings))
```

## 十九、encoder/decoder 形状不匹配错误修复

### 19.1 错误描述

训练启动后，在 Sanity Checking 阶段出现错误：

```
RuntimeError: The size of tensor a (24) must match the size of tensor b (25) at non-singleton dimension 2
```

**原因：** D 维度（25）不能被 `downsample`（8）整除：
- Encoder 输出 D = 25 // 8 = 3
- Decoder 输出 D = 3 * 8 = 24
- 输入 D = 25 ≠ 输出 D = 24，形状不匹配

### 19.2 问题分析

原始配置 `downsample: [8, 8, 8]` 对所有维度进行 8 倍下采样。

心脏 MRI 数据的 D 维度是时间帧（25帧或6帧），不应该进行空间下采样。

### 19.3 修复方案

修改配置，D 维度不下采样：

```yaml
# 修改前
downsample: [8, 8, 8]

# 修改后
downsample: [1, 8, 8]  # D维度不下采样
```

## 二十、encoder/decoder D 维度处理错误修复

### 20.1 错误描述

训练时出现形状不匹配错误：

```
Using a target size (torch.Size([1, 1, 25, 128, 128])) that is different to the input size (torch.Size([1, 1, 176, 128, 128]))
```

- 目标 x 的形状：`(1, 1, 25, 128, 128)`
- 输入 x_recon 的形状：`(1, 1, 176, 128, 128)`

**原因：** Encoder 和 Decoder 中的 Conv3d/ConvTranspose3d 对所有维度使用相同的 kernel_size，即使 D 维度 stride=1，kernel_size=4 也会改变 D 维度大小。

### 20.2 问题分析

**Encoder 中：**
- `nn.Conv3d(..., kernel_size=(4, 4, 4), stride=(1, 2, 2), padding=1)`
- D 维度：stride=1, kernel_size=4, padding=1
- 输出 D = (输入 D + 2*1 - 4) / 1 + 1 = 输入 D - 1

**Decoder 中：**
- `nn.ConvTranspose3d(..., kernel_size=4, stride=2, padding=1)`
- D 维度：stride=2，错误地进行上采样

### 20.3 修复方案

修改 Encoder 和 Decoder，让 kernel_size 匹配 stride：

**Encoder：**
```python
stride = tuple([2 if d > 0 else 1 for d in n_times_downsample])
kernel_size = tuple(max(2, s) for s in stride)
padding = tuple((k-1)//2 for k in kernel_size)
block.down = nn.Conv3d(..., kernel_size=kernel_size, stride=stride, padding=padding)
```

**Decoder (Upsample)：**
```python
self.conv_trans = nn.ConvTranspose3d(in_channels, in_channels, stride,
                                    stride=stride, padding=0)
```

### 20.4 形状变化

对于 `downsample: [1, 8, 8]`：

**Encoder：**
- 输入：`(1, 1, 25, 128, 128)`
- stride = (1, 2, 2), kernel_size = (2, 4, 4)
- 第一块后：`(1, 48, 25, 64, 64)`
- 第二块后：`(1, 96, 25, 32, 32)`
- 第三块后：`(1, 192, 25, 16, 16)`
- 输出：`(1, 8, 25, 16, 16)`

**Decoder：**
- 输入：`(1, 8, 25, 16, 16)`
- stride = (1, 2, 2), kernel_size = (1, 2, 2)
- 输出：`(1, 1, 25, 128, 128)`

## 二十二、DataLoader Collation 错误修复

### 22.1 错误描述

训练启动后，Sanity Checking 通过，但在第一个训练步骤出现错误：

```
RuntimeError: stack expects each tensor to be equal size, but got [216, 256, 25] at entry 0 and [256, 216, 25] at entry 1
```

**原因：** `__getitem__` 中存储了原始体积（`vol_cine4ch`、`vol_cinesax_0` 等），这些体积的 H,W 尺寸因患者不同而不同（216×256 vs 256×216），DataLoader 无法将它们 stack 成 batch。

### 22.2 问题分析

`__getitem__` 的数据流：

```
加载原始体积 (H, W, D)
    ↓
存储到 loaded_volumes
    ↓
取第一个体积 → _extract_patch → (128, 128, 25) → result["volume"]
    ↓
result["data"] = (1, 25, 128, 128)  ← 这个是对的
    ↓
遍历 loaded_volumes → result["vol_xxx"] = 原始体积  ← 这个没有经过 _extract_patch！
```

DataLoader collate 时会尝试 stack 所有 key，包括 `vol_cine4ch`、`vol_cinesax_0` 等，但这些 tensor 的 H,W 不一致。

### 22.3 修复方案

修改 `data_loaders/cardiac_dataset.py` 的 `__getitem__` 方法，对所有存储的体积都应用 `_extract_patch`：

```python
# 修改前
for mod_key, vol in loaded_volumes.items():
    if vol.ndim == 2:
        vol = vol[:, :, np.newaxis]
    elif vol.ndim == 4:
        vol = vol[:, :, :, 0]
    result[f"vol_{mod_key}"] = torch.from_numpy(vol).float()

# 修改后
for mod_key, vol in loaded_volumes.items():
    if vol.ndim == 2:
        vol = vol[:, :, np.newaxis]
    elif vol.ndim == 4:
        vol = vol[:, :, :, 0]
    vol = self._extract_patch(vol)  # ← 新增：统一 patch 尺寸
    result[f"vol_{mod_key}"] = torch.from_numpy(vol).float()
```

### 22.4 额外修复：NIfTI 数据格式兼容

修改 `_load_nifti_volume` 方法，处理不同格式的 NIfTI 数据：

- 4D 数据 (H, W, D, 1) → 移除 singleton 维度
- 3D 数据 (D, H, W) → 转置为 (H, W, D)（当 D > H,W 且 D > 30 时）
