### 2.4 修复 BiFlowNet 维度不匹配错误

**问题描述：**
- 训练开始后报错 `RuntimeError: The size of tensor a (25) must match the size of tensor b (24)`
- 错误发生在 BiFlowNet forward 的 U-Net 跳跃连接处

**原因分析：**
- Latent 的 D 维度为 25（奇数）
- BiFlowNet 使用 `sub_volume_size=8` 进行 unfold 操作
- 25 不能被 8 整除，导致下采样/上采样后维度不匹配

**修复方案：添加 padding 支持**

修改 `ddpm/BiFlowNet.py` forward 方法：
- 在 unfold 操作前，将输入 padding 到能被 `sub_volume_size` 整除
- 在 final_conv 后，裁剪回原始大小

**修改文件：**
- `ddpm/BiFlowNet.py` — forward 方法

**修改内容：**

```python
# 在 unfold 前添加 padding
pad_d = (p - x_IntraPatch.shape[2] % p) % p
pad_h = (p - x_IntraPatch.shape[3] % p) % p
pad_w = (p - x_IntraPatch.shape[4] % p) % p
if pad_d > 0 or pad_h > 0 or pad_w > 0:
    x_IntraPatch = F.pad(x_IntraPatch, (0, pad_w, 0, pad_h, 0, pad_d))

# 在输出时裁剪回原始大小
x = x[:, :, :ori_shape[0], :ori_shape[1], :ori_shape[2]]
```

### 2.5 修复 BiFlowNet einops Shape Mismatch 错误

**问题描述：**
- 训练启动后报错 `einops.EinopsError: Shape mismatch, 16 != 12`
- rearrange 模式 `'b (p1 p2 p3) c d h w -> b c (p1 d) (p2 h) (p3 w)'` 失败
- 输入 tensor shape: `[4, 16, 72, 8, 8, 8]`，`p1*p2*p3=3*2*2=12 ≠ 16`

**原因分析：**

| 计算来源 | D 维度 | p1 | p2 | p3 | 总 patch 数 |
|----------|--------|----|----|----|----|
| ori_shape_upscaled (padding 前) | 25×8=200 | 200//64=**3** | 2 | 2 | **12** ❌ |
| 实际 padded shape | 32×8=256 | 256//64=**4** | 2 | 2 | **16** ✅ |

- `ori_shape_upscaled` 在 padding 前计算，使用原始 shape `(25, 16, 16)`
- 但 unfold 操作在 padding 后执行，实际 shape 为 `(32, 16, 16)`
- `25*8//64=3`，`32*8//64=4`，导致 `3*2*2=12 ≠ 4*2*2=16`

**修复方案：**

在 padding 后、unfold 前，新增 `padded_shape_upscaled` 变量，用于 rearrange 的 patch 维度计算。

**修改文件：** `ddpm/BiFlowNet.py`

| 位置 | 修改内容 |
|------|----------|
| 第 674 行 (新增) | `padded_shape_upscaled = (x_IntraPatch.shape[2]*8, ...)` |
| 第 709 行 | `ori_shape_upscaled` → `padded_shape_upscaled` |
| 第 720 行 | `ori_shape_upscaled` → `padded_shape_upscaled` |

### 2.6 全面修复 BiFlowNet Padding 维度不匹配问题

**问题描述：**
- 修复 2.5 后仍报错 `RuntimeError: size of tensor a (25) must match size of tensor b (32)`
- 错误在 `x = x + h_Unet.pop(0)` 处
- 根本原因：仅修复了 einops reshape，但主路径 x 和 IntraPatch 路径 h_Unet 在所有交叉点都存在维度不匹配

**根本原因分析：**

输入 latent D=25 不是 sub_volume_size=8 的倍数，导致两条路径维度不一致：

| 路径 | D 维度变化 |
|------|-----------|
| 主路径 (x) | 25 → 25 → 25 → 12 → 6 → 12 → 24 |
| IntraPatch (h_Unet) | 25 → pad 32 → unfold → 重建 32 |

所有 `x + h_Unet` 和 `torch.cat((x, r))` 操作都会因维度不匹配而失败。

**修复方案：统一 padding 策略**

将 padding 操作提前到 `init_conv` 之前，让两条路径都在 padded 维度上工作，最后统一裁剪回原始尺寸。

**修改文件：** `ddpm/BiFlowNet.py` forward 方法

| 修改点 | 说明 |
|--------|------|
| 第 664-670 行 | padding 提前到 init_conv 之前，同时应用于 x 和 x_IntraPatch |
| 第 671 行 | `x_IntraPatch = x.clone()`（从已 padding 的 x 克隆） |
| 第 672 行 | `padded_shape_upscaled` 直接从 x 的 padded shape 计算 |
| 第 676-677 行 | init_conv 和 r 在 padded 维度上操作 |
| 第 723-740 行 | 恢复原始 h_Unet 添加逻辑（无需裁剪，维度自然匹配） |
| 第 752 行 | 最终裁剪回 `ori_shape` 保留 |

**修复后数据流：**
```
输入 [B,C,25,16,16] → pad → [B,C,32,16,16]
  ├─ x_IntraPatch: unfold → IntraPatchFlow → h_Unet [B,dim,32,16,16]
  └─ x: init_conv → [B,dim,32,16,16] → down/up → [B,dim,32,16,16]
       x + h_Unet → 维度匹配 ✅
  → final_conv → crop → [B,out,25,16,16]
```
